# Splunk AppInspect publishing-blocker check IDs.
#
# Any warning whose check_id appears in this file fails the
# splunk-ta-appinspect CI job, in addition to the unconditional
# `summary.failure > 0` / `summary.error > 0` gates.
#
# Derived from Splunkbase's app-publishing rules at
# https://dev.splunk.com/enterprise/docs/releaseapps/
# (last reviewed 2026-05-20). When AppInspect changes the check IDs
# upstream OR Splunkbase changes the blocker list, update this file
# AND the dev.splunk.com citation date above.
#
# Format: one check_id per line. Lines starting with # are comments.
# Trailing whitespace is ignored.

# Only IDs that are EXECUTED under `--included-tags cloud` belong
# in this list — a check that does not execute cannot be tripped,
# so listing it here gives false security. The CI gate enforces
# this with a presence assertion (every blocker_id must appear in
# the executed set or the job fails). Add an ID below only after
# confirming it shows up in appinspect.json's executed-checks set.

# Scripted inputs / search command implementations must declare a
# dispatch user. Authentication-gap risk if omitted. Executes under
# the `cloud` tag.

# app.conf [package] id must match the TA directory name and be
# absent of conflicting dependency declarations. Executes under the
# `cloud` tag.
check_for_dependencies_in_app_conf
